# 점수 저장 실패 롤백 — 설계 문서

> **작성일**: 2026-11-03
> **상태**: ✅ 완료

---

## 1. Context (목적)

점수 입력은 응답을 기다리지 않고 화면부터 바꾸는 낙관적 업데이트다.
기존에는 `PATCH /api/matches/:id`가 실패해도 화면 점수를 되돌리지 않아, 저장된 것처럼 보이다가 새로고침하면 점수가 사라졌다.
또 `useScoreModal`이 `updateScore`를 await하지 않아 실패가 처리되지 않은 Promise로 남았다.

## 2. Requirements (요구사항)

- [x] 저장 실패 시 해당 경기 점수를 서버에 마지막으로 저장된 값으로 되돌린다.
- [x] 사용자에게 실패 사실과 다시 입력하라는 안내를 보여준다.
- [x] 같은 경기를 연달아 수정했을 때, 이전 요청의 실패가 최신 입력을 덮어쓰지 않는다.
- [x] 응답 순서가 뒤바뀌어도 오래된 요청의 성공이 최신 확정 점수를 덮어쓰지 않는다.
- [x] 처리되지 않은 Promise rejection이 남지 않는다.

## 3. 기술 결정

| 방식 | 장점 | 단점 |
|---|---|---|
| 요청 직전 점수를 클로저에 저장 후 복원 | 가장 단순 | 연속 수정 시 오래된 실패가 최신 입력을 덮어씀 |
| 실패 시 전체 matches 재조회 | 서버와 확실히 일치 | 요청 1회 추가, 다른 진행 중 입력까지 덮어씀 |
| **매치별 확정 점수 + 최신 요청 번호 추적 (채택)** | 연속 수정 · 응답 역전에도 안전, API 추가 없음 | 상태 추적 코드가 조금 늘어남 |

판단 로직은 React와 무관한 순수 함수로 `src/utils/scoreSync.ts`에 두고 Vitest로 검증한다.

## 4. 데이터 흐름

1. `updateScore` → `sync.begin(matchId, 현재 점수)`로 요청 번호 발급 (처음이면 현재 점수를 확정값으로 기록)
2. 화면 점수 즉시 반영 후 `PATCH` 요청
3. 성공 → `sync.succeed()`: 더 최근 성공이 없을 때만 확정값 갱신
4. 실패 → `sync.fail()`: 이 요청이 해당 경기의 최신 요청일 때만 확정값 반환 → 화면 복원 + `ErrorBanner` 표시

## 5. 테스트 케이스

| ID | 시나리오 | 결과 |
|---|---|---|
| R01 | 단일 요청 실패 → 요청 전 점수로 복원 | ✅ |
| R02 | 성공 후 다음 요청 실패 → 성공한 점수로 복원 | ✅ |
| R03 | 더 최근 요청이 있으면 이전 요청 실패는 무시 | ✅ |
| R04 | 이전 요청 성공 + 최신 요청 실패 → 이전 요청 점수로 복원 | ✅ |
| R05 | 오래된 성공이 늦게 도착해도 최신 확정값 유지 | ✅ |
| R06 | 경기끼리 서로 영향 없음 | ✅ |
